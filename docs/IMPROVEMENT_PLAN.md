# 오늘의 말랑부적 — 맹점 분석과 개발 반영 계획

이 문서는 **지금 앱이 어떤 상태인지**를 보고,
아직 약한 네 가지(디자인, 처음 들어오게 하기, 다시 오게 하기, 재미)를 정리한 글입니다.

어려운 말은 되도록 풀어서 썼습니다.
중학생도 “그래서 다음에 무엇을 고치면 되는지”를 따라올 수 있게 쓰는 것이 목표입니다.

같이 보면 좋은 글:

- [INTRODUCTION.md](INTRODUCTION.md) — 이 앱이 무엇인지
- [ARCHITECTURE.md](ARCHITECTURE.md) — 코드가 어디에 있는지
- [DEPLOYMENT.md](DEPLOYMENT.md) — 토스에 올리는 방법

## 1. 이 프로젝트는 무엇인가?

**오늘의 말랑부적**은 토스 앱 안에서 열리는 작은 웹앱입니다.
이런 앱을 **미니앱**, 또는 **앱인토스(Apps in Toss)** 라고 부릅니다.

하는 일은 아주 단순합니다.

1. 하루에 한 번 부적 카드를 뽑습니다.
2. 카드에는 “오늘 이렇게 버텨 보자”는 가벼운 응원이 적혀 있습니다.
3. 광고를 보면 같은 날 한 번 더 뽑을 수 있습니다.
4. 두 번째로 나온 부적이 오늘의 부적이 됩니다.
5. 최근 7일 기록과 부적 24종 도감을 볼 수 있습니다.

진짜 점집, 사주, 운세 앱이 **아닙니다**.
“이 부적을 쓰면 운이 좋아진다”고 말하지 않습니다.
돈, 포인트, 쿠폰도 주지 않습니다.

지금은 이런 뼈대가 이미 있습니다.

| 있는 것 | 아직 약한 것 |
|---------|--------------|
| 홈 / 오늘 / 기록 / 도감 화면 | 부적이 이모지라서 기억에 덜 남음 |
| 부적 24종과 뽑기 규칙 | 친구가 들어올 길이 거의 없음 |
| 광고 보고 다시 뽑기 1회 | 내일 다시 올 이유가 약함 |
| 브라우저에 기록 저장 | 뽑고 나면 그날은 볼거리가 적음 |
| 분홍·크림색의 밝은 분위기 | 앱 아이콘이 아직 임시 그림 |
| 떠 있는 알약 탭바 (오늘/기록/도감) | 토스 검수용 미리보기 사진 최신화 |

한 줄로 말하면:

> **뼈대는 만들어져 있고, 사람을 불러오고 붙잡아 두는 장치는 아직 적다.**

그래서 아래 네 가지 맹점을 먼저 고치는 편이 좋습니다.

## 2. 맹점 ① 디자인 (부적 그림이 약하다)

### 지금 모습

- 부적 그림은 사진이나 일러스트가 아니라 **이모지**입니다.
  예: 기상 성공 부적 = 🌅, 고양이 기운 부적 = 🐱
- 앱 아이콘도 아직 임시 주소(`placehold.co`)입니다.
- 카드 모양은 거의 같고, 이모지와 글만 바뀝니다.
- 코드에는 `basic` / `special` / `seasonal` 등급이 있지만,
  뽑을 때 확률도 다르고, 카드 장식도 크게 다르지 않습니다.
- 시즌 부적이라고 적혀 있어도, 계절마다 바뀌는 그림은 없습니다.

### 왜 문제인가?

사람이 앱을 고를 때, 글보다 **그림**을 먼저 봅니다.

토스 검색, 추천, 홈 화면에 이 앱이 뜰 때도
아이콘과 미리보기 사진이 먼저 보입니다.
아이콘이 임시 네모이고, 안에도 이모지만 있으면
“귀여운 부적 앱”이라는 느낌이 잘 안 납니다.

또 부적 24장이 서로 비슷하면,
도감에서 자물쇠를 열어도 “와, 새 카드다”라는 기분이 약합니다.

### 의견

디자인을 거창한 게임처럼 바꿀 필요는 없습니다.
대신 **부적마다 얼굴이 다르게 보이게** 만드는 것이 먼저입니다.

좋은 방향:

- 무섭거나 종교처럼 보이는 그림은 쓰지 않습니다. (이미 정한 규칙)
- 종이 부적 + 말랑한 캐릭터처럼, 밝고 둥근 그림이 잘 맞습니다.
- 24장을 한 번에 명화처럼 그릴 필요는 없습니다.
  먼저 **공통 틀 1개 + 부적마다 다른 문양/색/캐릭터**면 충분합니다.
- 특별 부적, 시즌 부적은 테두리, 배경, 반짝임만 조금 다르게 해도
  “오늘은 조금 다른 카드가 나왔다”는 느낌을 줄 수 있습니다.

하지 말 것:

- 어두운 부적, 무속 상징, “효과가 세진다”는 장식
- 너무 많은 글씨로 카드를 채우기
- 아이콘만 예쁘고, 카드 안은 그대로 이모지로 두는 것

## 3. 맹점 ② 사용자 유입 (토스 안에서 어떻게 발견되나)

이 앱은 일반 앱스토어가 아니라 **토스 안**에서 발견됩니다.
문을 여러 개 열어 두지 않으면, 아는 사람만 들어오게 됩니다.

앱인토스 공식 문서에는 이런 입구가 있습니다.

| 입구 | 쉽게 말하면 | 우리 앱 지금 상태 |
|------|-------------|-------------------|
| 검색 (`search`) | 토스에서 “부적”, “오늘”을 찾아 들어옴 | 이름은 좋지만, 아이콘·미리보기 사진이 약함 |
| 전체 탭 추천 | 토스가 “이런 앱 어때요?” 하고 보여 줌 | 앱이 무엇을 하는지 한눈에 안 보일 수 있음 |
| 홈 인텔리 | 토스 홈에 잠깐 추천으로 뜸 | 설명 문장이 “접속 → 행동 → 결과”로 안 적혀 있음 |
| 최근 사용 | 한 번 쓴 사람이 다시 누름 | 다시 올 이유가 약하면 최근 목록에서도 식음 |
| 공유 (`external_share`) | 친구가 링크를 보냄 | **공유 기능이 아직 없음** |
| 알림 (`inbox`, `push`) | 알림을 누르고 들어옴 | **알림도 아직 없음** |
| 주요 기능 | 토스에서 기능 이름으로 바로 들어옴 | **아직 등록하지 않음** |

### 왜 문제인가?

코드만 잘 만들어도, 토스 안에 **간판**이 없으면 사람이 못 찾습니다.

지금 간판이 약한 이유:

1. 아이콘이 임시 그림입니다.
2. 미리보기 사진(스크린샷) 계획이 문서에 “최소 2장”만 있습니다.
3. 친구에게 보내는 버튼이 없습니다.
4. 토스 콘솔의 **주요 기능**을 아직 안 넣었습니다.
   (최대 3개. 누르면 앱의 특정 화면으로 바로 갑니다.)
5. 어디서 들어왔는지(`referrer`)를 기록하지 않습니다.
   그래서 “검색으로 많이 오나, 추천으로 오나”를 나중에 알기 어렵습니다.

### 의견 — 토스 안에서 쓸 전략

돈을 쓰는 큰 광고보다, **이미 있는 입구를 깨끗하게 쓰는 것**이 먼저입니다.

**1) 검색에서 잘 걸리게 하기**

사람들이 검색할 법한 말을 앱 소개에 넣습니다.
다만 거짓말은 안 됩니다.

- 좋은 예: “하루 한 장, 귀여운 응원 부적”
- 나쁜 예: “대박 운세”, “돈 복 부적”, “오늘 로또”

앱 이름 **오늘의 말랑부적**은 이미 잘 지어져 있습니다.
이름 옆에 짧은 설명을 꼭 붙이는 것이 좋습니다.

**2) 주요 기능 3개 등록하기**

토스 콘솔에는 기능을 최대 3개까지 등록할 수 있습니다.
누르면 그 화면으로 바로 갑니다.

추천 이름:

| 한국어 이름 | 영어 이름 | 이동 주소 |
|-------------|-----------|-----------|
| 오늘의 부적 뽑기 | Draw today charm | `intoss://today-lucky-charm/today` |
| 부적 도감 보기 | Charm collection | `intoss://today-lucky-charm/collection` |
| 최근 기록 보기 | Recent charms | `intoss://today-lucky-charm/history` |

이름 규칙: 10자 안, 이모지 금지, “~하기” 또는 명사형.

**3) 미리보기 사진**

심사에도 사진이 필요합니다.
유입에도 사진이 필요합니다.
아래 3장이면 충분합니다.

1. 홈에서 “뽑기” 버튼이 크게 보이는 화면
2. 부적 카드가 나온 화면
3. 도감에서 몇 장을 모은 화면

**4) 공유는 나중에, 다만 “자랑할 카드”부터**

앱인토스에는 공유 링크(`getTossShareLink`)가 있습니다.
친구에게 보내면 토스가 열리고, 우리 앱으로 들어옵니다.

주의:

- 현금, 포인트, 쿠폰을 주면 이 앱의 약속과 어긋납니다.
- 공유 리워드(초대하면 재화 주기)는 **쓰지 않는 것**을 권합니다.
- 대신 “오늘 나온 부적 카드 보내기”만 하면 됩니다.
  받는 사람은 앱에 들어와 **자기 부적도 뽑아 보게** 하면 됩니다.

**5) 어디서 들어왔는지 적어두기**

토스는 실행할 때 `referrer`라는 쪽지를 줍니다.
예: `search`, `home_intelligence`, `push`, `external_share`

처음에는 화면에 안 보여도 됩니다.
나중에 “어떤 문이 잘 열렸는지” 보려면 이 값이 꼭 필요합니다.

## 4. 맹점 ③ 재방문 (내일도 오게 만들기)

### 지금 모습

하루에 한 번만 뽑을 수 있어서, **습관**이 생기기 좋은 구조입니다.
하지만 뽑고 나면 그날은 거의 할 일이 없습니다.

- 알림이 없습니다. 내일 아침 “뽑을 시간이야”라고 말해 주지 않습니다.
- 연속으로 온 날을 세지 않습니다. (문서 뒷부분 할 일에는 적혀 있음)
- 기록은 최근 7일만 보여 줍니다.
- 저장이 이 휴대폰 브라우저(`localStorage`)에만 있습니다.
  데이터를 지우거나, 다른 폰으로 바꾸면 도감이 사라집니다.
- 홈 화면은 “이미 뽑았어요 / 아직 안 뽑았어요” 두 가지뿐입니다.

### 왜 문제인가?

습관 앱은 **빼먹으면 아까운 느낌**이 있어야 다시 옵니다.

지금은

- 안 와도 손해 볼 것이 없고
- 와도 어제와 같은 화면이며
- 기록이 사라질 수도 있습니다.

그러면 “귀엽네” 하고 한 번 쓰고 끝납니다.

### 의견

크게 세 층으로 나누는 것이 좋습니다.

**1층. 앱 안에서 내일의 이유를 보여 주기 (가장 먼저)**

- 연속 방문 숫자: “3일 연속으로 뽑았어요”
- 도감 빈칸: “아직 21장이 잠겨 있어요”
- 빠진 날: 기록에서 “어제 안 뽑음”이 보이면, 오늘은 뽑고 싶어집니다.
- 홈에 오늘의 부적을 작게 다시 보여 주기
  (지금 홈은 이름만 말하고, 카드는 오늘 탭에 가야 보입니다.)

이 층은 토스 허가가 거의 필요 없습니다. 코드만 고치면 됩니다.

**2층. 알림으로 불러오기**

앱인토스에는 **스마트 발송**이 있습니다.
매일 정해진 시간에 “오늘의 부적을 아직 안 뽑았어요”라고 보낼 수 있습니다.

꼭 지킬 것:

- 알림을 보내기 전에 **동의를 받아야** 합니다.
- 광고처럼 느껴지는 문장은 검수를 받습니다.
- “운세가 도착했다”, “놓치면 안 된다” 같은 말은 쓰지 않습니다.
- 좋은 예: “오늘의 말랑부적이 아직 없어요. 가볍게 한 장 뽑아 볼까요?”

알림은 하루에 한 번, 아침이나 점심이 적당합니다.
밤늦게, 여러 번 보내면 오히려 꺼립니다.

**3층. 기록이 안 사라지게 하기**

다시 왔는데 도감이 비어 있으면, 사람은 떠납니다.
브라우저 저장만 쓰는 한, 이 위험은 남습니다.

나중에 토스 저장소나 서버로 옮기는 일이
재방문과 직접 연결됩니다.

순서는 이렇게 가는 것이 좋습니다.

1. 연속 방문 + 홈에서 오늘 카드 보여 주기
2. 알림 동의 + 하루 한 번 알림
3. 저장소를 더 안전한 곳으로 옮기기

## 5. 맹점 ④ 흥미 유발 (왜 또 열고 싶을까)

### 지금 재미있는 점

이미 있는 재미도 있습니다.

- 하루에 한 장만 나와서, 기다림이 있습니다.
- 광고를 보면 한 번 더 뽑을 수 있어서, 작은 선택이 있습니다.
- 뽑을 때 🎴가 돌고, 카드가 내려오거나 커집니다.
- 도감에 자물쇠가 있어서 “아직 못 본 부적”이 있습니다.
- 문장이 가볍고 귀엽습니다. 점집처럼 무겁지 않습니다.

### 금방 심심해지는 이유

- 24장을 **똑같은 확률**로 뽑습니다.
  특별 부적, 시즌 부적이 이름만 특별합니다.
- 카드가 글이 많고, 그림이 적습니다.
- 뽑은 뒤 “친구에게 보여 주기”, “오늘 할 일 체크”가 없습니다.
- 계절이 바뀌어도 부적 목록이 그대로입니다.
- 도감을 다 모으면(또는 거의 모으면) 더 볼 것이 없습니다.
- 같은 부적이 또 나와도, “3번째 만남” 정도의 연출만 있고
  새로운 문장이나 작은 변화는 없습니다.

### 의견

흥미를 높이려면 **사행성**으로 가면 안 됩니다.
확률을 숨기거나, “강화”, “등급 업”, 돈을 거는 느낌은
이 앱의 규칙과 맞지 않습니다.

대신 **수집 + 오늘의 작은 이야기** 쪽이 맞습니다.

바로 넣기 좋은 것:

1. **연속 방문 표시**
   3일, 7일처럼 작은 꽃 표시만 있어도 “끊기기 싫다”가 생깁니다.
2. **부적마다 다른 뒷모습**
   그림이 없어도, 색과 문양만 바꿔도 도감이 게임처럼 보입니다.
3. **오늘 할 일 체크 한 칸**
   카드에 적힌 “오늘 해 볼 일” 옆에 체크하면,
   그날 앱을 한 번 더 열 이유가 생깁니다.
   (점수나 돈은 주지 않습니다. 동그라미만 그립니다.)
4. **같은 부적이 또 나오면 문장만 살짝 바꾸기**
   완전히 새 부적을 24장 더 만들기 전에,
   이미 있는 부적의 “두 번째 만남 문장”만 추가해도 됩니다.
5. **시즌 부적은 정말 그 계절에만**
   예: 여름에는 매운맛·더위, 겨울에는 체력·따뜻함.
   “지금 안 뽑으면 다음 계절까지 잠김”이 가장 건강한 희소성입니다.
6. **공유는 자랑용**
   “오늘 나는 지갑 방어 부적”처럼 카드 한 장을 보내는 것.
   받는 사람이 자기 것도 뽑게 만드는 것이 목표입니다.

넣지 말 것:

- 확률 공개를 가장한 과장 (“0.1% 전설”)
- 광고를 여러 번 보면 더 좋은 부적
- 돈, 포인트, 쿠폰
- 친구보다 더 좋은 운을 겨루는 랭킹

---

## 6. 네 가지가 서로 어떻게 이어지나

따로 고치면 힘이 빠집니다. 아래처럼 한 줄로 이어집니다.

```
예쁜 부적 그림
   → 검색/추천에서 눌러 보고 싶어짐 (유입)
   → 뽑은 카드를 친구에게 보내고 싶어짐 (유입 + 흥미)
   → 도감과 연속 방문이 아까워서 내일도 옴 (재방문)
   → 알림이 “아직 안 뽑았다”고 한 번만 불러 줌 (재방문)
```

그래서 개발 순서는 **그림 → 앱 안 습관 → 토스 간판 → 알림/공유** 가 안전합니다.
알림과 공유는 토스 검수가 있어서, 앱 안 재미보다 늦게 가는 편이 낫습니다.

## 7. 개발 반영 계획

큰 원칙:

- 운세가 진짜라는 말은 끝까지 쓰지 않습니다.
- 돈/포인트/쿠폰은 만들지 않습니다.
- 광고 다시 뽑기는 하루 1회를 지킵니다.
- 개인정보(이름, 전화)는 모으지 않습니다.
- 한 번에 다 만들지 않고, **작은 단계**로 올립니다.

### 0단계 — 준비 (코드보다 간판)

목표: 토스에 올렸을 때 “이게 무슨 앱인지” 보이게 하기

할 일:

- [x] 앱 아이콘 원본을 [public/app-icon.svg](../public/app-icon.svg)에 만들었다
- [ ] 콘솔에 올린 뒤 토스 파트너 콘솔에서 진짜 아이콘 주소로 바꾼다 (SDK 3.x부터 콘솔에서 등록)
- [ ] 미리보기 사진 3장을 찍는다 (홈, 카드, 도감)
- [ ] 파트너 콘솔 소개 글을 “하루 한 장 뽑기 → 응원 카드 → 도감에 모으기”로 쓴다
- [ ] 주요 기능 3개를 등록한다 (뽑기 / 도감 / 기록)
- [ ] 검색에 걸릴 안전한 단어만 적는다. 대박·운명·효험은 뺀다

완료의 기준:

- 임시 아이콘이 사라진다
- 콘솔에서 앱을 눌렀을 때 세 기능으로 바로 들어간다

예상 크기: 작음 (그림 작업 + 콘솔 입력)

할 일:

## 9. 나중에 효과가 있는지 보는 법

숫자로 보면 덜 헷갈립니다.
처음에는 거창한 분석보다 아래 네 가지만 봐도 됩니다.

1. **처음 연 사람 수** — 유입이 늘었는지
2. **다음날에도 연 사람 비율** — 재방문이 늘었는지
3. **뽑기까지 한 사람 비율** — 들어와서 실제로 썼는지
4. **공유를 누른 횟수** — 카드가 자랑할 만했는지

유입 경로는 `referrer`로 나눠 보면 좋습니다.
검색은 많은데 다음날 재방문이 적으면, 디자인이 아니라
**뽑고 난 뒤 화면**을 고쳐야 합니다.
반대로 재방문은 좋은데 사람이 적으면,
앱 안이 아니라 **간판(아이콘, 검색, 주요 기능)** 을 고쳐야 합니다.

## 10. 이 문서가 말하는 결론

오늘의 말랑부적은 이미 “하루 한 장 응원 카드”라는 마음이 분명합니다.
그 마음을 지키면서 사람을 모으려면, 운세를 세게 만들면 안 됩니다.

필요한 것은 네 가지뿐입니다.

1. **부적에 얼굴(그림)을 주기**
2. **토스 검색·주요 기능·사진으로 문을 열기**
3. **연속 방문과 알림으로 내일의 이유를 만들기**
4. **도감·시즌·공유로 작은 재미를 쌓기**

이 순서로 올리면, 앱의 약속(과장 금지, 현금 보상 금지, 하루 한 번)을
깨지 않고도 더 많은 사람이 가볍게 다녀갈 수 있습니다.
